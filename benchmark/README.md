# Benchmark

Одинаковая проверка каждой версии поиска и ответа. Набор вопросов и эталонов фиксируется до настройки поиска, затем выдача и ответы сравниваются с ним.

## Состав

- `questions.json` — 10 обычных вопросов и 5 вопросов-ловушек;
- `results/` — сохранённые прогоны;
- корпус — `corpus/docs.jsonl`, 30 документов D01–D30.

## Формат `questions.json`

Список объектов. Обычный вопрос:

```json
{
  "id": "Q01",
  "type": "normal",
  "question": "Можно ли передать персональные данные клиентов подрядчику, который обучает нашу модель?",
  "relevant": ["D04", "D15", "D22"],
  "reference": "Можно по поручению оператора с договором, где указаны цели и меры защиты; по GDPR — договор с процессором по ст. 28."
}
```

Ловушка:

```json
{
  "id": "T01",
  "type": "trap",
  "question": "Какой штраф по КоАП грозит за утечку персональных данных?",
  "relevant": [],
  "reference": "NO_ANSWER"
}
```

Примеры условные: ID и формулировки появятся после сборки корпуса.

## Правила составления вопросов

- У каждого обычного вопроса не меньше трёх релевантных документов. Релевантные документы размечает человек.
- Вопросы равномерно покрывают корпус: каждый акт и каждая тема из `spec/tech/rag.md` встречаются хотя бы в одном вопросе.
- Вопросы формулируются своими словами, как спросил бы продакт или разработчик, а не копированием фрагментов статей.
- Эталон — короткий ответ, который можно проверить по релевантным документам.
- Ловушки правдоподобны и близки к теме, но ответа в корпусе нет: штрафы, сроки уведомления регулятора, законы других стран, нормы вне выбранных статей.
- Вопросы и эталоны пишутся до настройки поиска и после этого не меняются. Для подбора `MIN_SCORE` используется отдельный черновой набор.

## Метрики

Поиск — по 10 обычным вопросам, глубина `k = 5`:

- **Recall@5** — доля релевантных документов, найденных в первых пяти, усреднённая по вопросам:
  Recall@5 = (1 / |Q|) · Σ |R(q) ∩ Top5(q)| / |R(q)|.
- **MRR** — средний обратный ранг первого релевантного документа:
  MRR = (1 / |Q|) · Σ 1 / rank(q); если в первых пяти релевантного нет, слагаемое равно 0.

Ответ — по всем 15 вопросам:

- **Accuracy** — доля полностью правильных ответов из 10 обычных. Ответ правильный, если совпадает по смыслу с эталоном и не содержит утверждений, которых нет в документах. Оценивается вручную.
- **Correct Rejection Rate** — доля корректных отказов из 5 ловушек. Любой ответ по существу, догадка или выдуманная норма — ошибка.

Ловушки в метрики поиска не входят.

## Запуск

```bash
python -m benchmark
```

Скрипт строит индекс, прогоняет все 15 вопросов, считает Recall@5 и MRR и сохраняет выдачу и ответы в `results/`. Accuracy и Correct Rejection Rate заполняются вручную по сохранённым ответам.

## Что сохраняется в `results/`

Один прогон — один файл `ГГГГ-ММ-ДД_описание.json`. В нём настройки (предобработка, `k₁`, `b`, `MIN_SCORE`), выдача по каждому вопросу (ID и баллы), ответ модели и посчитанные метрики.
