# Подключение интерфейса к API

Состояние на 27.11.2026. Фронтенд интегрирован с сервером из ветки `feature/api`; объединённая работа ведётся в `feature/frontend-api`. В `feature/frontend-api` включена ветка `origin/feature/api` с аккаунтами и рабочим пространством. В рамках подключения клиента Python-модули API, поиска, ответов и корпус не менялись. Полный контракт — в [architecture.md](architecture.md), текущее поведение экранов — в [описании интерфейса](../product/interface.md).

## Границы частей

- Эмилия: `app/index.html`, `app/styles.css`, `app/app.js`, `app/api.js`, `app/data.js`.
- Александра: сервер `app/server.py`, HTTP-контракт и вызов поиска и модели.
- Елена: `app/search.py`, корпус и проверка качества RAG.

Все сетевые запросы интерфейса проходят через `app/api.js`. Он по умолчанию обращается к `/api/search` на том же origin. Сервер FastAPI раздаёт и фронтенд, и API.

Для macOS добавлен `start.command`: он запускает существующий сервер и открывает HTTP-адрес приложения. Открытие `app/index.html` по `file://` перенаправляется на `http://localhost:4173` с сохранением раздела; отправка запросов из файлового origin не используется.

## Поиск и ответ — подключено

`POST /api/search`:

```json
{ "query": "Нужно ли согласие на обработку персональных данных?", "jurisdiction": null }
```

`query` — непустая строка до 2000 символов. `jurisdiction` — `ru`, `eu` или `null`. Фронтенд отправляет именно эти два поля. Сервер пока не принимает историю диалога, поэтому сохранённая переписка не влияет на следующий запрос.

Ответ:

```json
{
  "status": "ok",
  "answer": "Ответ модели с метками [D13]",
  "clarification_question": null,
  "citations": [
    {
      "id": "D13",
      "doc_title": "GDPR (Регламент ЕС 2016/679)",
      "article": "ст. 6",
      "excerpt": "Фрагмент из корпуса",
      "jurisdiction": "eu",
      "edition": "Редакция документа в корпусе",
      "url": "https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng"
    }
  ]
}
```

| Состояние | Поведение интерфейса |
|---|---|
| `ok` | Показывает `answer`, выделяет известные метки `[id]`, создаёт карточки цитат. Нажатие на метку раскрывает нужную карточку. |
| `insufficient` | Показывает `answer`, если он задан, иначе «В документах нет информации по этому вопросу». Это обычный ответ; кнопки повтора ошибки нет. |
| `need_clarification` | Показывает `clarification_question` как ответ в том же диалоге. |
| Ожидание | Показывает индикатор и кнопку остановки; параллельная отправка в том же чате блокируется. |
| `422` | Сообщает, что запрос должен содержать 1–2000 символов. |
| `502` | Сообщает о сбое поиска или модели и предлагает повторить запрос. |
| Сетевая ошибка | Сообщает об отсутствии связи с сервером и предлагает повтор. |
| Таймаут | Сообщает, что ответ не пришёл за отведённое время, и предлагает повтор. |
| Некорректный JSON/формат | Показывает ошибку формата; не создаёт пустой ответ. |

Таймаут запроса чата — 210 секунд, учитывая 180 секунд ожидания LLM на сервере. Кнопка остановки прерывает ожидание в браузере; остановка вычислений на сервере зависит от его реализации. Повтор использует тот же вопрос и выбранную при его отправке юрисдикцию.

Текст экранируется перед показом. Ссылки источников допускают только HTTP/HTTPS. Метка превращается в кнопку только при наличии цитаты с таким `id`. Текст, цитаты, вопрос и `id` сохраняются вместе при добавлении ответа в избранное.

## Каталог

`app/data.js` содержит метаданные 27 статей, сгруппированных из 30 фрагментов `corpus/docs.jsonl`. Поля `fragmentIds` связывают статьи с документами RAG. Ответы чата не формируются из этого каталога: они всегда запрашиваются у сервера.

Идентификатор карточки статьи и идентификатор фрагмента различаются. Например, карточка `152fz:6` объединяет `D03` и `D04`; метка в ответе ссылается именно на `D03` или `D04`. После изменения корпуса каталог `app/data.js` нужно сверять с новой версией `docs.jsonl`.

## Аккаунты и рабочее пространство

Маршруты из [architecture.md](architecture.md#аккаунты-и-рабочее-пространство) подключены без дополнительных настроек. Клиент использует `credentials: 'same-origin'`; сервер устанавливает HttpOnly-cookie. Пароли и токены в браузерное хранилище не записываются.

| Действие | Запрос клиента |
|---|---|
| Проверка сессии при открытии | `GET /api/auth/me` |
| Регистрация | `POST /api/auth/register` с `{ name, email, password }` |
| Вход | `POST /api/auth/login` с `{ email, password }` |
| Выход | `POST /api/auth/logout` |
| Загрузка истории и избранного | `GET /api/workspace` |
| Импорт / сохранение чата | `PUT /api/chats/{id}` с целым чатом |
| Удаление чата | `DELETE /api/chats/{id}` |
| Добавление / удаление статьи | `PUT / DELETE /api/favorites/articles/{id}` |
| Добавление ответа | `PUT /api/favorites/answers/{message_id}` с `{ chatId, question, message, savedAt }` |
| Удаление ответа | `DELETE /api/favorites/answers/{message_id}` |

Гость пишет без входа; его состояние живёт только в памяти страницы. Перезагрузка удаляет гостевую переписку и черновики. Звёздочка открывает форму входа и запоминает выбранную статью или ответ до закрытия формы.

После успешного входа или регистрации клиент останавливает незавершённые запросы гостя, фиксирует текущие чаты, выполняет для каждого `PUT` с прежним `id`, затем получает `/api/workspace`. После загрузки добавляет выбранную перед входом статью или ответ в избранное. Незавершённый вопрос можно повторить в аккаунте. При сбое импорт остаётся в памяти страницы, доступна кнопка «Повторить»; повторные `PUT` заменяют чаты с теми же идентификаторами. До окончания загрузки изменение чатов блокируется. Не следует перезагружать страницу до завершения переноса: гостевая копия не хранится на диске.

История и избранное вошедшего пользователя загружаются с сервера. В `localStorage` с ключом `pravo-ryadom:preferences-v1:<user.id>` сохраняются только черновики и активный чат. Старая локальная история версии `workspace-v2` не читается и автоматически не импортируется; данные другого браузера появляются после повторного входа и загрузки страницы, без фонового обновления между устройствами.

Запись выполняется последовательно в пределах страницы. Чат отправляется перед ожиданием ответа и после его завершения; текущий `pending` не заменяется на экране серверным `interrupted`, пока запрос ещё выполняется. Подтверждённый сервером чат обновляет локальное отображение только для актуальной версии. Избранное и удаление чата меняются на экране после подтверждения сервера. Неудачные операции сохраняются в памяти для повтора, последующая успешная запись того же объекта заменяет устаревшую ошибку. При перезагрузке загружается последняя сохранённая серверная версия.

Выход дожидается очереди сохранения, завершает серверную сессию и убирает личные данные с экрана. Если сохранить часть изменений не удалось, об этом сообщается. Ответы с `401` от рабочего пространства очищают текущее представление аккаунта и предлагают повторный вход. Ответ `401` от формы входа означает неверную почту или пароль. `503` входа означает временно недоступную авторизацию; гостевой поиск остаётся доступен. При сетевом сбое или `503` рабочего пространства доступна кнопка повторного подключения / записи. При `422` клиент сообщает об ограничениях; формы учитывают пароль 8–128 символов, вопрос до 2000 символов, чат до 200 сообщений.

Настройки при обычном запуске не нужны. Для альтернативных маршрутов настройка располагается перед `api.js`:

```html
<script>
  window.NAVIGATOR_CONFIG = {
    chatEndpoint: '/api/search',
    authBase: '/api/auth',
    workspaceBase: '/api'
  };
</script>
```

Адреса авторизации и рабочего пространства должны оставаться на том же origin, чтобы использовать текущую cookie-сессию. Запуск PostgreSQL, Redis и миграций описан в [README](../../README.md#аккаунты-и-хранилище).

## Будущий API каталога

В текущем сервере нет маршрута выдачи каталога. Для следующего этапа можно отдельно задать `catalogEndpoint: '/api/catalog'`. Ожидается `GET`, возвращающий массивы `documents` и `articles` с полями `app/data.js`: у документа обязательны `id`, `short`, `title`, `jurisdiction`, `url`; у статьи — `id`, `documentId`, строковый `number`, `title`, `url`. Идентификаторы уникальны и стабильны; допускаются латинские буквы, цифры, `:`, `.`, `_` и `-`.

## Следующие шаги команды

| Задача | Кто участвует | Что требуется |
|---|---|---|
| Общий pull request в `main` | Команда | Проверить объединённую ветку `feature/frontend-api` с аккаунтами и рабочим пространством |
| Учёт контекста чата, если потребуется | Александра и Елена; изменение запроса клиента — Эмилия | Отдельно согласовать контракт и использование предыдущих сообщений. Сейчас отправляются только `query` и `jurisdiction` |
| Обновление корпуса и каталога | Елена и Эмилия; при API каталога — Александра | Сохранять стабильные идентификаторы фрагментов, обновлять карточки статей и `fragmentIds` |
| Сквозная проверка внешней LLM | Команда | Запустить интерфейс с настоящим поиском и настроенной моделью; проверить ответы, отказ и соответствие меток цитат |

Для RAG сохраняется правило: метка `[D13]` в тексте соответствует `id: "D13"` в `citations`. Карточка использует `doc_title`, `article`, `excerpt`, `jurisdiction`, `edition` и `url`. Подключение аккаунтов не меняет запрос поиска и формат цитат.

## Проверенное состояние

- Набор бэкенда, поиска, бенчмарка, аккаунтов и рабочего пространства: 71 тест прошёл с настоящими PostgreSQL и Redis, без пропусков.
- В Chrome проверены повтор частично выполненного импорта без дубликатов, вход во время ожидания ответа и повтор прерванного запроса, восстановление юрисдикции черновика, гостевой режим, перенос нескольких чатов при регистрации, сохранение выбранного ответа после входа, история и оба вида избранного после перезагрузки и в другом браузере, разделение аккаунтов, выход и удаление чата с сохранением избранного ответа.
- Проверены `401` истёкшей сессии, `503` авторизации и записи, повтор сохранения, черновики, отсутствие локальной истории гостя и мобильная раскладка.
- Ранее проверены успешный HTTP-запрос поиска, отказ, ошибки 422/502, отсутствие связи, повтор без дубликата, таймаут и остановка ожидания; настоящий BM25 с заглушкой LLM и отображение тестового `need_clarification`.
- Прогон текущего интерфейса с внешней LLM ещё не выполнялся. Прогоны модели из `benchmark/results/` относятся к проверке серверного поиска и ответа.
