# Архитектура

Из каких частей состоит приложение, как они соединены и кто за какую отвечает. Поиск и ответ подробно описаны в `rag.md`.

## Части приложения

| Часть | Что делает | Где лежит | Статус |
|---|---|---|---|
| Интерфейс | Экраны навигатора | `app/index.html`, `app/styles.css`, `app/app.js` | Прототип есть |
| API | Принимает запрос от интерфейса и возвращает ответ | `app/server.py` | Планируется |
| Поиск | BM25 по корпусу | `app/search.py` | Планируется |
| Ответ | Вызов LLM по найденным фрагментам | `app/answer.py` | Планируется |
| Корпус | Тексты статей | `corpus/` | Планируется |
| Benchmark | Вопросы и результаты проверки | `benchmark/` | Планируется |

Backend: Python и FastAPI. Интерфейс остаётся на HTML, CSS и JS.

## Путь запроса

```
Интерфейс → API → Поиск → Ответ (LLM) → API → Интерфейс
```

1. Интерфейс отправляет вопрос в API.
2. API получает от поиска 5 лучших фрагментов.
3. Если фрагментов недостаточно, API возвращает статус `insufficient`, LLM не вызывается.
4. Иначе фрагменты передаются в LLM, и она возвращает ответ с цитатами.
5. API возвращает интерфейсу готовый ответ.

## API

**`POST /api/search`**

Запрос:

```json
{ "query": "string", "jurisdiction": "ru | eu | null" }
```

Ответ:

```json
{
  "status": "ok | need_clarification | insufficient",
  "answer": "string | null",
  "clarification_question": "string | null",
  "citations": [
    { "doc_title": "", "article": "", "excerpt": "", "jurisdiction": "", "edition": "", "url": "" }
  ]
}
```

- `ok` — найдены источники, есть ответ и цитаты.
- `need_clarification` — не хватает данных, интерфейс показывает `clarification_question`.
- `insufficient` — источников недостаточно.

**`GET /api/documents`** — список документов для экранов «Источники» и «Сравнение». Пока этот список записан в `app/app.js`.

## Данные

- Корпус: файлы в `corpus/`.
- Закладки: сейчас хранятся в браузере (`localStorage`).
- Ключ LLM: переменная окружения, не в репозитории.

## Запуск

- Сейчас (только интерфейс): `python3 -m http.server 4173 -d app`, затем `http://localhost:4173`.
- Когда появится API: одна команда запускает и API, и интерфейс. Команду записать здесь.

## Проверка

- Интерфейс: пройти основной сценарий вручную (вопрос, результаты, открыть источник, сохранить).
- API: тесты в `tests/` на три статуса ответа.
- Поиск и ответ: benchmark из `rag.md`.
