## Путь запроса

```
Интерфейс → API → Поиск → Ответ (LLM) → API → Интерфейс
```

1. Интерфейс отправляет вопрос в API.
2. API получает от поиска 5 лучших фрагментов.
3. Если фрагментов недостаточно, API возвращает статус `insufficient`, LLM не вызывается.
4. Иначе фрагменты передаются в LLM, и она возвращает ответ с цитатами.
5. API возвращает интерфейсу готовый ответ.

## API

**`POST /api/search`**

Запрос:

```json
{ "query": "Нужно ли согласие на обработку персональных данных?", "jurisdiction": null }
```

`query` содержит 1–2000 символов после проверки пустого ввода; `jurisdiction` — строка `ru`, строка `eu` или JSON `null`. Контракт не содержит истории переписки.

Ответ:

```json
{
  "status": "ok | need_clarification | insufficient",
  "answer": "string | null",
  "clarification_question": "string | null",
  "citations": [
    { "id": "", "doc_title": "", "article": "", "excerpt": "", "jurisdiction": "", "edition": "", "url": "" }
  ]
}
```

- `ok` — найдены источники, есть ответ и цитаты.
- `need_clarification` — не хватает данных, интерфейс показывает `clarification_question`.
- `insufficient` — источников недостаточно.

Каталог статей сейчас задан метаданными из корпуса в `app/data.js`. `POST /api/search` публичный и обрабатывает каждый вопрос отдельно: история переписки в модель и поиск не передаётся (решение команды). Аккаунты, история и избранное на сервере описаны в разделе «Аккаунты и рабочее пространство»; текущее поведение фронтенда — в `frontend-api.md`.

## Аккаунты и рабочее пространство

Статус на 27.11.2026: сервер и интерфейс подключены. Раздел описывает действующее хранение истории чатов и избранного для вошедших пользователей.

**Поведение для пользователя**

- Гость задаёт вопросы без входа. Его переписка живёт только в памяти страницы и пропадает при перезагрузке; на сервере и в `localStorage` ничего не сохраняется.
- Гость не может добавлять в избранное: попытка предлагает войти.
- При входе или регистрации интерфейс импортирует текущие гостевые чаты в аккаунт, затем загружает рабочее пространство с сервера.
- Вошедший пользователь видит историю чатов и избранное на любом устройстве. Черновики ввода и выбранный чат остаются в браузере отдельно для каждого аккаунта.
- Предыдущие сообщения чата в модель и поиск не передаются.

**Сессии**

Сессия хранится в Redis, ключ `session:<id>`, значение — id пользователя. Браузер получает cookie `session_id` (HttpOnly, SameSite=Lax, Path=/). Срок жизни 3600 секунд, продлевается при каждом запросе вошедшего пользователя. Пароль хранится только как хэш scrypt с индивидуальной солью. Почта приводится к нижнему регистру.

**Маршруты авторизации**

| Маршрут | Тело | Успех | Ошибки |
|---|---|---|---|
| `POST /api/auth/register` | `{ "name", "email", "password" }` | `201`, `{ "user": { "id", "name", "email" } }`, пользователь сразу вошёл | `409` почта занята, `422` неверные поля |
| `POST /api/auth/login` | `{ "email", "password" }` | `200`, `{ "user": ... }` | `401` неверная почта или пароль, `422` |
| `GET /api/auth/me` | — | `200`, `{ "user": ... }` | `401` нет сессии |
| `POST /api/auth/logout` | — | `204`, cookie удаляется | — |

Ограничения полей: имя 1–100 символов, пароль 8–128 символов, почта корректного формата.

**Маршруты рабочего пространства** (нужна сессия, иначе `401`)

| Маршрут | Назначение |
|---|---|
| `GET /api/workspace` | Всё одним ответом: `{ "chats": [...], "favoriteArticles": ["152fz:6"], "favoriteAnswers": [...] }` |
| `PUT /api/chats/{chat_id}` | Создать или заменить чат целиком вместе с сообщениями (идемпотентно); используется и для импорта гостевых чатов. `200` с сохранённым чатом |
| `DELETE /api/chats/{chat_id}` | Удалить чат вместе с сообщениями; `204`. Избранные ответы остаются |
| `PUT /api/favorites/articles/{article_id}` | Добавить статью в избранное; `204` |
| `DELETE /api/favorites/articles/{article_id}` | Убрать статью; `204` |
| `PUT /api/favorites/answers/{message_id}` | Сохранить копию ответа: `{ "chatId", "question", "message", "savedAt" }`; `204` |
| `DELETE /api/favorites/answers/{message_id}` | Убрать ответ; `204` |

Формат чата совпадает с тем, что использует интерфейс: `{ "id", "title", "jurisdiction", "createdAt", "updatedAt", "messages": [ { "id", "role", "text", "jurisdiction", "createdAt", "status", "errorText", "citations", "replyStatus" } ] }`. Сообщение со статусом `pending` сервер сохраняет как `interrupted`. Идентификаторы уникальны в пределах пользователя. Ограничения: до 200 сообщений в чате, `text` до 20000 символов, `title` до 200, `id` до 64 символов из `A–Z a–z 0–9 _ -`; нарушение даёт `422`. При одновременной записи с двух устройств побеждает последняя.

**Хранилище**

| Таблица PostgreSQL | Ключ | Основные поля |
|---|---|---|
| `users` | `id` | `name`, `email` (уникальная), `password_hash`, `created_at` |
| `chats` | `(user_id, id)` | `title`, `jurisdiction`, `created_at`, `updated_at` |
| `messages` | `(user_id, chat_id, id)` | `position`, `role`, `text`, `jurisdiction`, `status`, `error_text`, `reply_status`, `citations` (jsonb), `created_at`; удаляются вместе с чатом |
| `favorite_articles` | `(user_id, article_id)` | `created_at` |
| `favorite_answers` | `(user_id, message_id)` | `chat_id`, `question`, `message` (jsonb, копия ответа), `saved_at` |

Схема создаётся миграциями Alembic. Redis хранит только сессии. При `401` рабочего пространства клиент убирает данные аккаунта с экрана и предлагает повторный вход; при `503` и сетевых сбоях предоставляет повтор загрузки или сохранения. Подробности очереди записи и импорта — в `frontend-api.md`.

**Включение.** Хранилище подключается переменными `DATABASE_URL` и `REDIS_URL`. Если они не заданы, маршруты `/api/auth/*`, `/api/workspace`, `/api/chats/*` и `/api/favorites/*` отвечают `503`, а интерфейс работает в гостевом режиме. Тесты существующих маршрутов не требуют базы.

## Правила API

- `jurisdiction`: `ru`, `eu` или `null`. Если указана, поиск идёт только по документам этой юрисдикции.
- API берёт из поиска `K = 5` фрагментов (переменная `RAG_K`). Если фрагментов нет или балл лучшего ниже `MIN_SCORE` (переменная `RAG_MIN_SCORE`, по умолчанию 3.0, подбирается по benchmark), возвращается `insufficient`, LLM не вызывается.
- `need_clarification`: механизм есть (`answer.needs_clarification`), LLM в этом случае не вызывается. Решение на контрольную точку 2: правила нет, функция всегда возвращает «уточнение не нужно». Если юрисдикция не выбрана, поиск идёт по всем документам, ответ собирается по найденным фрагментам обеих юрисдикций, в цитатах указана юрисдикция каждого. Причины: бенчмарк считает только ответ и отказ, а статус `need_clarification` не входит ни в то, ни в другое; сценарий сравнения РФ и ЕС (сценарий 4) требует показывать обе юрисдикции сразу. Правило для уточнений можно ввести после КТ2 (решает продукт).
- Цитаты собираются из найденных фрагментов, а не из текста модели. Если ответ ссылается на `id`, которых нет среди найденных, они отбрасываются. Если не осталось ни одной проверенной ссылки, статус `insufficient`.
- Отказ модели: LLM по инструкции возвращает ровно `NO_ANSWER`. Если маркер есть в ответе, ответ считается отказом (`insufficient`), даже когда в тексте упомянуты `[id]`. По маркеру benchmark считает Correct Rejection Rate.
- К полям цитаты добавлено `id` (нужно интерфейсу, чтобы связать метки вида `[D01]` в ответе с карточками источников).
- Ошибки: `422` для пустого или неверного запроса, `502` при сбое поиска или LLM.
- Контракт поиска: `search(query, jurisdiction, k)` возвращает фрагменты по убыванию `score` с полями `id`, `doc_title`, `jurisdiction`, `article`, `text`, `url`, `edition`, `score`.

## Данные

- Корпус: файлы в `corpus/`.
- Для вошедших пользователей история, избранные ответы и статьи хранятся на сервере (PostgreSQL), сессии — в Redis. Черновики ввода и активный чат остаются в браузере (`localStorage`). Гостевая переписка хранится только в памяти страницы.
- Каталог интерфейса — метаданные 27 статей в `app/data.js`; 30 фрагментов для поиска находятся в `corpus/docs.jsonl`. Ответы чата всегда поступают из API.
- Ключ LLM: переменная окружения, не в репозитории.

## Запуск

Нужен Python 3.10 или новее. На macOS доступен запуск двойным щелчком по `start.command`. Через терминал:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.server:app --port 4173
```

Затем открыть `http://localhost:4173`. Сервер отдаёт интерфейс и API. Открытие локального HTML перенаправляется на этот адрес; сам сервер должен быть запущен. Причина исправления: файловый адрес приводил к запросу `file:///api/search` вместо HTTP.

По умолчанию работают заглушки поиска и LLM. Настоящий режим включается переменными окружения (PowerShell):

```powershell
$env:RAG_SEARCH = "real"
$env:RAG_MIN_SCORE = "3.0"
$env:LLM_BASE_URL = "https://openrouter.ai/api/v1"
$env:LLM_MODEL = "nvidia/nemotron-3.5-super-vl:free"
$env:LLM_API_KEY = "<ключ>"
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| RAG_SEARCH | stub или real | stub |
| RAG_K | число фрагментов | 5 |
| RAG_MIN_SCORE | порог отказа | 3.0 |
| LLM_BASE_URL | адрес API провайдера; без него работает заглушка | не задан |
| LLM_MODEL | идентификатор модели | не задан |
| LLM_API_KEY | ключ провайдера; хранится только в окружении | не задан |
| DATABASE_URL | подключение к PostgreSQL; без него аккаунты отключены | не задан |
| REDIS_URL | подключение к Redis | не задан |

Хранилище для аккаунтов поднимается из корня проекта: `docker compose up -d` (PostgreSQL, Redis, Adminer). Adminer открывается на `http://localhost:8082` (система PostgreSQL, сервер `postgres`). Миграции: `alembic upgrade head`.

Для локального запуска с аккаунтами задайте (PowerShell):

$env:DATABASE_URL = "postgresql+psycopg://navigator:navigator@localhost:5434/navigator"
$env:REDIS_URL = "redis://localhost:6380/0"

## Проверка

- Интерфейс: отправить вопрос в чат, раскрыть цитату по метке `[id]`, сохранить ответ, проверить историю после перезагрузки; отдельно проверить отказ, пустой ввод и отсутствие связи.
- API: тесты в `tests/` на три статуса ответа.
- Поиск и ответ: benchmark из `rag.md`.
- Запуск: python -m pytest

При интеграции фронтенда выполнены 51 существующий тест и проверки Chrome на ширинах 360–1960 px: состояния ответа и ошибок, цитаты, избранное, история, навигация, формы и анимации. Проверен настоящий BM25 с заглушкой LLM; сквозной прогон интерфейса с внешней моделью остаётся отдельной задачей. Ручные шаги — в [описании интерфейса](../product/interface.md#ручная-проверка-интерфейса).
