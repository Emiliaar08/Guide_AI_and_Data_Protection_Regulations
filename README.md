# Право рядом — навигатор по нормативке в области ИИ и защиты данных

Приложение помогает находить положения 152-ФЗ, GDPR и AI Act по вопросу пользователя. Основной экран — чат: вопрос отправляется в API, ответ содержит метки источников, например `[D13]`, и раскрывающиеся карточки с цитатами. Диалоги и избранное сохраняются в браузере.

## Запуск

На macOS можно открыть `start.command` двойным щелчком: он запускает сервер и открывает приложение в браузере. Если нужный сервер уже работает, используется существующий процесс. При первом запуске создаётся виртуальное окружение и устанавливаются зависимости.

Нужен Python 3.10 или новее. Из корня проекта:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.server:app --port 4173
```

Откройте `http://localhost:4173`. Один сервер раздаёт интерфейс и `POST /api/search`; отдельно запускать `http.server` для работы чата не нужно. На macOS/Linux вместо `python` можно использовать установленный `python3.13` или Python из виртуального окружения (`.venv/bin/python`).

При открытии `app/index.html` как файла интерфейс автоматически переходит на `http://localhost:4173`, сохраняя выбранный раздел. Для работы запросов сервер должен быть запущен: адреса `file:///.../index.html` и `file:///api/search` не предоставляют HTTP API.

По умолчанию поиск и LLM работают на заглушках сервера. Для подключения настоящего поиска и модели задаются переменные окружения (PowerShell):

```powershell
$env:RAG_SEARCH = "real"
$env:RAG_MIN_SCORE = "3.0"
$env:LLM_BASE_URL = "https://openrouter.ai/api/v1"
$env:LLM_MODEL = "nvidia/nemotron-3.5-super-vl:free"
$env:LLM_API_KEY = "<ключ провайдера>"
```

На macOS/Linux аналогичные переменные задаются через `export`, например `export RAG_SEARCH=real`. Для проверки настоящего BM25 без обращения к внешней модели достаточно `RAG_SEARCH=real`, оставив `LLM_BASE_URL` незаданным.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `RAG_SEARCH` | `stub` или `real` — источник поиска | `stub` |
| `RAG_K` | число фрагментов для формирования ответа | 5 |
| `RAG_MIN_SCORE` | порог отказа поиска | 3.0 |
| `LLM_BASE_URL` | адрес API провайдера; без него используется заглушка LLM | не задан |
| `LLM_MODEL` | идентификатор модели провайдера | не задан |
| `LLM_API_KEY` | ключ только в окружении, без записи в код и репозиторий | не задан |

## Интерфейс и API

- Чат открывается сразу. На боковой панели — новый диалог, источники, избранное и история.
- Каждый вопрос отправляется в `POST /api/search` с полями `query` и `jurisdiction` (`ru`, `eu` или `null`). Дополнительная настройка адресов для обычного запуска не нужна.
- Метки `[D01]` в ответе раскрывают соответствующую карточку: цитату, юрисдикцию, редакцию и ссылку на первоисточник.
- `insufficient` — нормальный результат: «В документах нет информации по этому вопросу». Поддерживается и `need_clarification`.
- Пока сервер готовит ответ, виден индикатор. Можно остановить ожидание. Таймаут клиента — 210 секунд, с учётом серверного таймаута LLM в 180 секунд.
- Для `422`, `502`, отключённого сервера и таймаута предусмотрены отдельные сообщения. Повтор запроса не создаёт второй экземпляр вопроса.
- История, черновики, избранные статьи и ответы хранятся в `localStorage`. Избранный ответ остаётся после удаления чата.
- API пока обрабатывает каждый вопрос отдельно. История диалога сохраняется для пользователя, но не отправляется в модель: текущий контракт сервера не принимает контекст переписки.
- Каталог интерфейса содержит метаданные 27 статей из 30 фрагментов `corpus/docs.jsonl`. Фильтры показывают статьи выбранного документа.
- Формы входа и регистрации сохранены для будущей авторизации. Маршрутов аккаунтов и серверной синхронизации истории в текущем бэкенде нет.

Для другого адреса API можно перед `api.js` задать `window.NAVIGATOR_CONFIG = { chatEndpoint: '/api/search' }`. Будущие `authBase` и `catalogEndpoint` подключаются независимо. Подробности — в `spec/tech/frontend-api.md`.

## Проверка

В окружении без переменных `RAG_*` и `LLM_*`:

```bash
python -m pytest
```

Для ручной проверки интерфейса на заглушках:

1. Отправить «Нужно ли согласие на обработку персональных данных?» — появятся ответ и источник `[D01]`.
2. Нажать `[D01]` — откроется цитата с ссылкой на документ.
3. Спросить «Во сколько библиотека открыта в воскресенье?» — появится нормальный отказ без ошибки.
4. Отправить пустую строку — форма попросит ввести вопрос без запроса к серверу.
5. Сохранить ответ, перезагрузить страницу и открыть историю и избранное.
6. Остановить сервер в терминале, отправить сообщение в уже открытом интерфейсе — появится сообщение о связи. После запуска сервера повторить запрос.

Бенчмарк поиска и ответов:

```bash
python -m benchmark --answers --name <имя прогона>
```

Для настоящих ответов нужны `LLM_*`. Метрики, ручная разметка и результаты сохранены в `benchmark/README.md`.

## Структура

- `app/index.html` — оболочка чата, меню и SVG-иконки.
- `app/styles.css` — оформление, крупный текст и адаптация под мобильные экраны.
- `app/app.js` — диалоги, отображение ответов и цитат, история, избранное, источники и формы авторизации.
- `app/api.js` — запросы к серверу, таймауты, отмена и обработка сетевых ошибок. Ответы чата всегда берутся из API.
- `app/data.js` — метаданные статей корпуса и темы для начала диалога.
- `start.command` — запуск сервера и браузера на macOS.
- `app/server.py` — API и раздача фронтенда.
- `app/answer.py` — запрос к LLM и проверка цитат.
- `app/search.py`, `app/search_stub.py` — BM25 и заглушка поиска.
- `corpus/` — 30 нормативных фрагментов и скрипт сборки корпуса.
- `benchmark/` — вопросы, метрики, прогоны и результаты.
- `tests/` — автоматические тесты бэкенда, поиска и бенчмарка.
- `spec/product.md`, `spec/product/scenarios.md` — описание продукта и пользовательские сценарии.
- `spec/tech/architecture.md`, `spec/tech/rag.md`, `spec/tech/frontend-api.md` — архитектура, RAG и подключение интерфейса.
- `CHANGE_HISTORY.md` — журнал изменений.
